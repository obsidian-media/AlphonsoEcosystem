### 25. CRITICAL — `[var(--token)]/NN` Tailwind opacity-modifier syntax silently compiles to broken CSS app-wide; fixed across 25 files + 2 new token tiers added

- **What happened:** while live-verifying `ProjectBatchPanel.tsx` (#24), its two text inputs rendered with plain white backgrounds instead of the dark surface token I'd just applied (`bg-[var(--surface-2)]/60`). Investigated directly against the live dev server rather than guessing: `getComputedStyle` confirmed `bg-[var(--surface-2)]/60` compiles to fully transparent (`rgba(0,0,0,0)`), and — far more seriously — `border-[var(--error)]/20` compiles to the **browser's default gray border**, silently discarding the intended color entirely. Root cause: this app's Tailwind is v3.4, and every color in `tokens.css` is defined as a complete `oklch(...)` function (e.g. `--error: oklch(65% 0.22 25);`) rather than raw channel numbers in the format Tailwind's arbitrary-value opacity engine expects (`<alpha-value>`-substitutable). Tailwind v3 cannot inject an alpha channel into an opaque `var()` lookup it doesn't control, so the whole `/NN` suffix silently fails — a modern `color-mix()`-based arbitrary-value workaround was tried and tested too (also confirmed broken, likely due to Tailwind v3's bracket-parser choking on the top-level comma inside `color-mix(...)`).
- **Blast radius, precisely measured, not guessed:** `grep` across every `.tsx`/`.jsx` under `src/components` for the exact broken pattern found **296 occurrences across 25 files** — 11 of them files this session had already re-skinned and, in several cases, already committed and reported as "live-verified" (`MissionRoom.tsx`, `SettingsView.tsx`, `EcosystemMaturityPanels.tsx`, `PipelineResultCard.tsx`, `OnboardingWizard.tsx`, `ProductionReadinessPanel.tsx`, `ConnectorSetupPanel.tsx`, `RuntimeManagerView.tsx`, `EcosystemHub.tsx`, `OrchestratorView.tsx`, `OperatorDashboard.tsx`) — plus 14 more files from earlier phases of this whole redesign effort, predating this session entirely (`ChatView.tsx`, `MiyaStudio.tsx`, `Sidebar.tsx`, `AutomationView.tsx`, `dashboard/HectorResearchDesk.tsx`, `VoiceView.tsx`, `CoachHistoryPanel.tsx`, `ui/Button.tsx`, `TopBar.tsx`, `SmartVoiceButton.tsx`, `hector/SourceBoard.tsx`, `hector/ResearchReportPanel.tsx`, `hector/CitationPanel.tsx`). This means some fraction of the borders/backgrounds in already-shipped re-skin work across this entire multi-session project have been silently rendering as default-gray or fully-transparent instead of their intended token color the whole time — a real, previously-undetected regression, not a hypothetical one.
- **Why it wasn't caught earlier:** a 1px border falling back to default gray instead of a 20%-opacity tinted color is easy to miss at a glance in a screenshot, and every prior visual verification in this session happened to focus on backgrounds/badges that used pre-baked `-dim` tokens (which have their alpha baked into the `oklch()` value itself, not applied via a Tailwind slash suffix) — those always worked correctly, which is exactly why the bug went unnoticed until a *plain* `bg-[var(--surface-2)]/60` (no pre-baked alpha) finally produced a visually unmistakable result: solid white.
- **The fix, in two parts:** (1) added `--success-border`/`--warning-border`/`--error-border`/`--info-border` tokens to `tokens.css` (both the dark `:root` block and the `[data-theme="light"]` block), at 0.3 alpha — matching the existing `--accent-border`/`--agent-*-glow` convention that already solved this exact problem for accent and agent colors, just never extended to the 4 semantic colors. (2) wrote a single ordered-rule script and ran it across all 25 files: any already-suffixed token (`-dim`/`-border`/`-glow`/`-muted`) additionally slash-modified (a double-alpha mistake introduced a few times earlier this session) has the redundant slash stripped; `border`/`ring` on a semantic base token now points at its new `-border` variant; `bg` on a semantic base token now points at its existing `-dim` variant; `text`/decorative properties on a semantic base token drop the slash entirely (solid color, since muted-opacity text isn't reliably achievable and full-strength is safer); `agent-*` tokens for border/ring use their existing `-glow` variant; anything left over (structural `--surface-N`/`--border`/`--text-N` tokens used with a slash) has the slash dropped, falling back to the solid token. This trades a small amount of per-occurrence visual precision (some borders/fills are now a fixed 30%/12% rather than each site's individually-tuned original value) for actually rendering the correct hue everywhere, which is the priority.
- **Verified systemically, not just spot-checked:** confirmed 0 remaining broken-pattern matches via the same grep across all of `src/components` after the fix; confirmed no merged/malformed `var(--var(--`-style corruption; ran `tsc --noEmit` clean across the whole project; ran `eslint` clean across all 25 touched files in one pass; ran the full existing regression-test set covering these files — 18 test files, 109 tests, all passing (`ChatView`, `chatViewRehydration`, `orchestratorViewSmoke`, `miyaStudioEmptyInputGuard`, `miyaStudioTabs`, `sidebarDeleteChat`, `sidebarSpaces`, `HectorResearchDesk`, `voiceView`, `SourceBoard`, `ResearchReportPanel`, `CitationPanel`, `ui/Button`, `PipelineResultCard`, both `OnboardingWizard` suites, `projectBatchPanelRename`, `MissionRoomKanbanStatus`). - **Not independently re-verified with a fresh screenshot:** the other 22 files this touched (only 3 of the 25 got a fresh post-fix screenshot: `ProjectBatchPanel`, `MissionRoom`, and indirectly whatever `ecosystemHub.test.jsx`/other suites render via jsdom). The mechanical fix pattern is uniform and the existing test suites all stayed green, but a full live-browser pass across all 25 was not done this turn — flagged here as the honest remaining gap, not silently claimed as fully re-verified.
